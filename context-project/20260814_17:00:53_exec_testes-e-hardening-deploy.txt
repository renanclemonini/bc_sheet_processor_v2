## 5. Guard: pull sem nada deployável (polimento do update-prod.sh)

### `spa/spa-swarm/new-rebuild.sh`

- `SEM_DEPLOY='^templates/\|^README\.md$\|^tests/\|^\.playwright-mcp/\|^context-project/'`.
- Se pull trouxe **apenas** arquivos sem deploy: rsync de `templates/` (se alterados — bind
  mount, Jinja2 recarrega sozinho), cria o marcador `.deploy-skipped`, `exit 0` — **sem** entrar
  no poll de 5 min do GHCR nem falhar o wrapper.
- Código alterado ou nada novo → deploy normal (inalterado).

### `spa/spa-swarm/update-prod.sh`

- `rm -f .deploy-skipped` no início (marcador de execução anterior).
- Após o `new-rebuild.sh`: se o marcador existe → aviso explícito
  ("⚠ Update pulado… Sem deploy de imagem; templates, se alterados, já foram sincronizados
  pelo new-rebuild.sh"), **pula** o `sudo rsync` redundante e remove o marcador; senão → rsync
  normal. Confirmação `docker stack services` sempre roda.

### `.gitignore`

- Adicionada a linha `.deploy-skipped` (o marcador não pode ir parar num commit).

### Validação (sandbox local, sem push real)

- Sandbox em /tmp: clone local simulando a VM + remoto "fake" (git clone --bare) + stubs para
  `sudo`/`docker`; depois removido. Sem qualquer contato com o GitHub real.
- **Cenário 1 — push misto (código + docs):** deploy + rsync de templates.
- **Cenário 2 — push só de docs/testes:** "ℹ️ Apenas arquivos sem deploy…" → "✅ Nada a
  deployar" (exit 0) → wrapper imprime "⚠ Update pulado" e não roda o rsync → marcador
  removido. (Antes do guard: 5 min de poll + `exit 1` + rsync abortado.)
- **Cenário 3 — push só de templates:** sem deploy, rsync executado (index atualizado em /srv).
