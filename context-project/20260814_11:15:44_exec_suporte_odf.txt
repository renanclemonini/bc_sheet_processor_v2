## 7. Tooling de deploy (mesma sessão)

### `spa/spa-swarm/new-rebuild.sh` — fluxo otimizado (minimizar downtime)

O `spa/spa-swarm/rebuild.sh` foi mantido **intacto** para comparação. O `new-rebuild.sh`
passou a ter o fluxo: git pull → TAG derivada do **ref remoto** (`origin/${BRANCH}`, o
commit que o GHCR buildou — independe da branch local/detached HEAD) com `export` →
poll de espera da publicação no GHCR (lógica já existente) → **`docker pull` da tag
(pré-download fora da janela de deploy)** → `docker stack deploy` (swap stop-first com
a imagem já local, janela de segundos). Caminho "só templates → rsync" permanece.

Justificativa: sem o pre-pull, o swarm baixaria a imagem durante o swap do container,
estendendo o downtime de segundos para minutos. Downtime zero absoluto não é possível
com `mode: host` + `replicas: 1` + `stop-first` (documentado no docker-stack.yml).

### `.dockerignore` — contexto de build enxuto

Adicionados: `refatoracao-by-ia/`, `.playwright-mcp/`, `*.txt`, `**/*.txt`.
(`__pycache__/` já estava ignorado.) Validação: build de teste confirmou 0 arquivos
`.txt` e ausência das pastas dentro da imagem (contexto ~217KB contra ~700KB+ antes).

### Fora do escopo (decisão do usuário, tratado depois)

- `deploy.sh` ainda usa o fluxo antigo (TAG sem `export` → stack deploya `latest`)
- `new-rebuild.sh` não promovido a oficial / não removido
- `paths-ignore` do workflow GHCR inalterado
