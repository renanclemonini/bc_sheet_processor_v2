## 3. Tooling de deploy

### `spa/spa-swarm/update-prod.sh` (novo — fluxo oficial em 1 comando)

- Evento da sessão: novo wrapper que executa, em ordem: `new-rebuild.sh` (pull → TAG remota →
  espera GHCR → pre-pull → stack deploy) → `sudo rsync -a --delete templates/
  /srv/bc-sheet-processor/templates/` (sempre — interface atualizada) → `docker stack services`
  (confirmação).
- `set -e` + `cd "$(dirname "$0")/../.."` (roda de qualquer diretório). Falha no deploy aborta
  **antes** do rsync (evita UI nova sobre backend velho). Sem smoke test embutido (evita poluir o n8n).
- Uso: a partir de agora, qualquer atualização = `./spa/spa-swarm/update-prod.sh`.
  Primeiro uso num host exige rodar o `new-rebuild.sh` antigo uma vez (bootstrap — puxa o repo
  e o próprio script).

### `spa/spa-swarm/new-rebuild.sh` (fix `71a97f9`)

- Removido o **early-exit** que encerrava com "Nada novo para atualizar" (`ANTES == DEPOIS`) sem
  deployar — comportamento que ocultou o rsync na sessão anterior (incidente do "Already up to date").
- Agora **sempre aplica o deploy** (TAG derivada de `origin/${BRANCH}`), mantendo o rsync apenas
  para o caso "só templates mudaram".

### Permissões dos scripts (`106bb32`)

- `clean-swarm-output-files.sh`, `new-rebuild.sh` e `update-prod.sh` commitados com modo `100755`
  (executáveis no servidor logo após o pull).
