## 2. Aprendizados — Docker Swarm (deploy de produção)

- **`external: true` = você cria.** O Swarm jamais cria secret marcado como external;
  o deploy falha com `secret not found` se ele não existir. Criação tem que estar no
  caminho do deploy, não só no setup inicial do host.
- **Secrets são imutáveis.** Não existe "update": só `docker secret rm` + `create`.
  O container em execução mantém o valor antigo até ser recriado (próximo deploy).
- **`env_file:` é ignorado pelo Swarm.** Interpolação `${VAR}` no stack file acontece
  no momento do `docker stack deploy`, a partir do shell que executa (o
  `new-rebuild.sh` faz `set -a; . ./.env; set +a` exatamente para isso). Sem fonte
  confiável de `.env`, `TAG`/`WORKERS`/`N8N_WEBHOOK_URL` saem vazios.
- **Sensível vs não-sensível:** credenciais podem ir para secrets (`/run/secrets/`,
  fora do `docker inspect`); o `entrypoint.sh` lê os arquivos e exporta como env var
  para o `config.py`. Não-sensível continua como `environment:` interpolado.
- **TAG imutável derivada do ref remoto** (`origin/<branch>`) — o servidor pode estar
  em detached HEAD/branch local defasada; o que importa é o commit que o GHCR buildou.
- **Fluxo do deploy:** `git pull` → TAG do ref remoto → poll no GHCR (workflow em
  andamento) → `docker pull` (fora da janela de downtime) → ensure secrets →
  `docker stack deploy`. `templates/` é bind mount: entra por `rsync`, não por imagem.
- **Porta `mode: host` + `replicas: 1`** força `order: stop-first` (dois containers
  não ocupam a 8000 no mesmo host) — downtime breve esperado em cada deploy.

### Pegadinha de self-update (bash)

Script que faz `git pull` de si mesmo: o bash lê o arquivo em buffer no início da
execução; o `git pull` atualiza o disco, mas o processo em andamento continua com o
snapshot antigo. Consequência prática: a **1ª execução após o merge pode rodar o
`new-rebuild.sh` velho** e falhar (`secret not found`); a 2ª pega a versão nova.
Bootstrap seguro: `git pull` manual antes do `./update-prod`, ou rodar 2x.

### Invocação via symlink

`update-prod` na raiz → `./spa/spa-swarm/update-prod.sh`. O padrão antigo
`cd "$(dirname "$0")/../.."` usa o diretório do **link** (`.`), não do alvo, e caía em
`/home/renanclemonini`. Padrão correto aplicado nos 10 scripts do `spa-swarm`:

```bash
cd "$(dirname "$(readlink -f "$0")")/../.."
```

`readlink -f` resolve o symlink antes do `dirname` (GNU coreutils; ok no Rocky Linux
de produção e no dev Linux).
