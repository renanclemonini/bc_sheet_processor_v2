## 0. Objetivo

Planilhas com coluna de nome rotulada `primeiro nome` (em vez de `nome`) e telefone rotulado
`número`/`numeros` falhavam com `Formato de planilha não reconhecido`. Exemplo real do erro:

```
❌ Erro: Formato de planilha não reconhecido. Colunas encontradas: primeiro nome, telefone, etiquetas
```

Causa raiz: `detectar_padrao` exigia match **exato** de `nome`/`nomes` para o padrão de 3 colunas —
`primeiro nome` só era aceito no padrão de 4 colunas (que exige `sobrenome`). A coluna de telefone
também não reconhecia `número`/`numeros`.

---

## 1. Decisões da sessão (definidas com o usuário)

- **`número` é telefone de verdade** — incluídas as variantes `número`, `números` e `numeros`
  (headers só são lowercased, não perdem acento); singular/plural conforme convenção das outras tuples.
- **Nome aceito no padrão 3 colunas**: `nome`, `nomes`, `primeiro nome`, `primeiros nomes`
  (nova constante `COLUNAS_NOME_3COL = COLUNAS_NOME + COLUNAS_PRIMEIRO_NOME`).
- **Precedência 4 → 3** no `detectar_padrao`: sem isso, planilha real de 4 colunas
  (`primeiro nome, sobrenome, telefone, etiquetas`) passaria a casar no padrão 3 e quebraria o
  split nome/sobrenome — regressão guardada por teste.
- **AGENTS.md criado** — preferência permanente: toda validação de backend via `poetry run pytest`,
  sem simulações/arquivos temporários ad-hoc (evita desperdício de tempo e tokens).
- **Regra de git:** apenas `poetry run pytest` na verificação — **nada de commit/push**
  (toda decisão de git é do usuário).
